# INTENT-T18：性能压测、降级演练、封版与提审

## 1. 背景与目标
交付闸门。目标：**成功率 ≥98%、首字 <2s、95 分位 ≤15s 全部实测达标，提审 Checklist A–E 全项打勾，完成最小壳试审**。

## 2. 范围
**做**：压测脚本与报告、降级演练（LLM 超时/报错/内容安全全拦三场景）、Checklist A–E 逐项核验、最小壳试审策略执行、audit_status 记录、驳回预案。
**不做**：新功能（封版后只修 bug 与合规话术）。

## 3. 输入
- 交接包第七节提审 Checklist（A 主体资质 / B 隐私 / C 内容合规 / D 技术项 / E 提审策略）全量条目
- PRD M8-5 审核应急预案、第 8 节 Gate
- T15 audit_status 埋点

## 4. 产出
```
scripts/load-test.js                     # create/poll 并发压测（可配并发数与时长）
docs/stress-report.md                    # 压测报告：成功率/P95 延迟/降级触发率
docs/release-checklist.md                # Checklist A–E 落地为勾选表，每项附证据（截图/脚本输出）
docs/rejection-playbook.md               # 驳回预案：话术类 24h 整改流程；类目类换挂资讯类目流程；最多硬提 2 次
docs/audit-log.md                        # 每次提审记录（版本、时间、结果、整改项）
```

## 5. 实现要点
- 压测目标（Checklist D）：生成成功率 ≥98%；首字 <2s；95 分位 ≤15s。方法：50/100/200 并发三档 × 各 10 分钟；监控云函数错误率、LLM 供应商限流、数据库读写冲突。
- 降级演练三场景注入：①LLM 12s 超时 ②LLM 返回非法 JSON 连续 3 次 ③msgSecCheck 全拦——预期均走规则引擎降级（degraded=true，用户无感，3001 不应大规模出现）。
- Checklist 关键复核点：LLM Key 仅存云函数环境变量（前端 grep）；全站文案红词 0 命中（tools/check-redline.js 报告存档）；海报字段白名单与 AIGC 元数据；查单补发上线；隐私勾选清单与实际收集一致；拒绝授权主流程可用。
- 试审策略：首提最小壳（核心链路 + 合规组件，灵感小铺/说明书等可置灰）验证类目与话术口径；被拒 → 按预案 24h 整改或换类目，第 2 次被拒触发 Gate 0 掉头评审；每次结果写 audit_status 埋点与 audit-log。
- 封版流程：feature freeze → 仅 P0 bug → 全量回归（核心旅程 12 条用例）→ 版本 tag。

## 6. 验收标准
- [ ] 三档压测报告达标（≥98% / <2s / P95 ≤15s），未达标项有整改记录
- [ ] 三个降级场景演练通过，降级期间用户体验无报错
- [ ] release-checklist.md A–E 全项打勾且附证据（Checklist 完成即交接包 DoD 达成）
- [ ] 首提提交成功并记录 audit_status；被拒时 24h 内出整改版
- [ ] 回归 12 条核心用例全绿；版本打 tag 存档
