## 1. 产品目标

三个正交目标，任一目标的成功不应以牺牲另一目标为代价。

**目标一（用户价值）：让新生儿父母在 15 分钟内拿到 3–5 个"全家能通过、能上户口、讲得出出处"的名字候选。**
衡量：首次生成完成率 60–80%；单次会话收藏 ≥1 个名字的用户占比 ≥55%；会话时长中位数 ≤ 8 分钟。

**目标二（增长）：把"名字卡片/家人投票"做成自然的家庭群传播链路。**
衡量：生成完成后分享率 15–30%；分享回流转化率 ≥20%；WNKU（周度成功生成并保存名字的去重用户数）为北极星指标，上线 8 周内周环比正增长。

**目标三（合规生存）：在审核与舆情两个维度做到"零测算语义、零未成年人信息留存、零诱导"。**
衡量：提审一次通过（或驳回后 48 小时内整改通过）；高危词全局扫描 0 命中；未成年人相关字段落库量为 0（技术性验证，非抽样）。

**明确不做为目标的**：不做玄学准确性（无"准不准"这个概念）、不做名字评分排名、不做社交社区、不做 UGC 内容沉淀。

## 2. 用户故事（5 个场景）

1. **产后病房的妈妈（核心）**：宝宝出生 5 天，出院前要定名办出生证明。她在病床上单手操作，没有耐心填 12 个字段。她希望打开就能看到几个像样的名字，再慢慢挑。→ *对应 M1 极简首屏 + M2 秒出第一批候选。*

2. **被长辈施压的爸爸（长辈推动型）**：爷爷坚持要"按生辰算一算"才肯点头。他需要的不是更准的算法，而是一套**能讲给爷爷听、让爷爷点头的解释框架**：这个名字出自哪本书、是什么意思、好不好写、上户口有没有麻烦。→ *对应 M4 长辈视角说明 + 命名说明书导出。*

3. **异地家庭的全家投票**：夫妻在深圳，父母在成都和潮汕。爸爸把 4 个候选发到家庭群，请大家点"喜欢"，并想确认"用潮汕话念会不会有问题"。→ *对应 M3 方言谐音检测 + M4 家人共选投票。*

4. **追求不撞名的年轻父母**：明确不想叫"梓涵/沐宸"，想要小众但不生僻、别人念得出来、政务系统打得出来的字。→ *对应 M3 重名度/字频可视化 + 政务兼容提示。*

5. **准备开咖啡馆的小老板（B 端）**：想了 20 个店名都注册不下来，需要一个能同时看"字号美感 + 近似商标风险 + 域名是否还在"的工具。→ *对应 M7。*

## 3. 用户研究洞察摘要（来自瑞思 Reese）

- **核心人群**：产后 0–3 个月新生儿父母——唯一同时具备「硬性截止日期（出生证明/户口）」「全家参与」「高付费意愿」三要素的人群。次人群：长辈推动型用户。
- **底层动机排序**：①好听顺口（方言要过关）②能上户口不返工（用字须在《通用规范汉字表》8105 字内）③不撞名但不生僻 ④有出处、能讲故事 ⑤**长辈/全家通过（最被低估的一项）** ⑥不要吓我（要祝福，不要断语）。
- **已判定为伪需求**：「父母性格描述」无用户侧证据支持 → 改造为「寄寓期望标签」（健康/坚韧/豁达/温润/聪慧…），或直接跳过；「五行补缺精确度」用户无法验证，其真实功能是"说服长辈的话术武器" → 用「长辈视角说明 + 可验证的客观维度」替代（见 §8）。
- **风格化的真相**：真风向是「古风雅致、有出处、小众不撞名」。「韩系/日系」与「长辈认可」「能上户口」冲突且有舆情风险 → 移到 M6 泛命名模块。风格化的产品价值是**筛选器**——帮用户在 50–80 个候选里快速分组、对抗选择错觉，而非美学分类。
- **旅程四大流失点**：①表单过长（价值未兑现先付成本）②等待生成（AI 直出 2 分钟被明确吐槽太慢；"秒出"又显随意，**5–15 秒为疑似最优区间**）③结果均值回归（全是梓涵/沐宸/泽/铭）④全家通不过。
- **分享驱动力**：名字卡片发家庭群求投票、"帮我选"式求助分享。**红线**：不得做「转发解锁」（违反 3.2.1 诱导分享）。

## 4. 竞品与合规约束（来自竞析 Compa）

### 4.1 平台规则原文级约束
1. 《常见拒绝情形》**3.2.4**：禁止测试类内容，示例含「算命，抽签，星座运势等」。
2. 微信运营专员驳回口径（4 个独立案例）：「涉及**算卜算运势、算命、付费取名**等内容，属于平台未允许内容」。**案例 B：免费 + 删除吉凶 + 改为打分 + 有免责声明，两次整改后仍被驳回。** → 改名话术无效；产品本身不得带测算语义；**连"名字打分/评分/测试"都算测算**。
3. 类目库无「取名」类目 → 只能挂靠「工具 – 信息查询」或「资讯 – 信息资讯服务」，天然存在类目不符风险。
4. 抖音侧明文将「风水命理、算命、**解梦**、冥婚」列为封建迷信 → 想法 B 在任何主流平台均无生存空间。

### 4.2 AIGC / 支付 / 隐私硬门槛
- **AIGC 类目**：腾讯云开发文档明示「深度合成类目仅向非个人主体开放，个人主体无法申请」。第三方大模型 API 路线另需：厂商算法备案截图 + **含算法名称/应用场景/备案编号的合作协议**（仅购买 token 不够）；或走微信云开发 AI 获取「在用证明」（需企业认证 + 云环境 ≥3 个月）。
- **AIGC 标识义务**（2025-09-01 施行）：显式标识「AI 生成」须**全程固定展示**，不得角落小字；隐式标识须写入文件元数据 AIGC 字段。
- **隐私**：运营规范 15.1.3 禁止「要求用户输入出生日期才可使用功能」→ 生辰只能是可选增强项，不填也必须可用；15.1.3.2 拒绝授权不得阻断服务；15.12.6 禁止对他人生日等个人信息做展示 → 社区/分享展示必须脱敏。「宝宝精确出生时间 + 父母姓名 + 家庭情况」可识别未满 14 周岁自然人 → 落入 PIPL 敏感个人信息，需监护人同意 + 专门处理规则。
- **虚拟支付**：小程序内虚拟商品必须走 `wx.requestVirtualPayment`（全终端强制），安卓费率约 1%、iOS 12%；个人主体无法开通 → 个人主体仅能依赖流量主广告（UV ≥ 500 可开通）。

### 4.3 高危词库（全局禁用，运行时 + CI 双重拦截）
测算、算命、占卜、卜卦、批命、命理、八字（作测算依据）、五行补缺、喜用神、五格数理、三才五格、吉凶、祸福、转运、改运、改命、化解、消灾、招财、破财、克父克母、克夫克妻、注定、前世、因果、业障、犯太岁、开光、灵符、法事、流年运势、合婚、宜忌、预测、精准、必、一定。
**衍生禁用**：任何形式的分数/评分/评级/Rank/百分比"契合度/匹配度/好运指数"。

## 5. 数据与技术约束（来自数析 Metric）

- **本质模型**：起名 = **80% 确定性规则 + 20% 生成**。本地完成用字白名单、笔画、平仄、谐音、敏感词；大模型只负责「在合法解空间内挑好听的组合 + 写寓意」。
- **成本**：单次 ¥0.002–0.034；1000 次/天 → 月成本 ¥50–1,000（中位 ¥150–350）。瓶颈是获客与合规，不是算力。
- **方案**：原生 + 微信云开发 CloudBase，首版 18–30 人天，首版现金 ¥1,000–3,000（不含人力）。
- **P0 工程兜底**：①取名用字白名单（不在白名单即丢弃重生成）②诗词出处**本地三元组校验**（作者, 篇名, 原句 全中才展示，否则不显示出处理由）③敏感词 + 不雅谐音 + 贬义字过滤（msgSecCheck + 自建表）④免责声明全链路覆盖（首页/结果页/分享卡片/海报）。
- **模型幻觉率**（SuperCLUE-Faith 2025-05）：doubao-1.5-pro 4.11% / qwen-max 12.35% / DeepSeek-V3 13.83% / DeepSeek-R1 21.02% / Qwen3-235B 28.92%。**推理模型幻觉更高，选模型不能只看聪明**；诗歌体裁主要错误类型是「张冠李戴」→ 出处必须本地校验，不能信模型。
- **指标基线**：北极星 WNKU；首次生成完成率 60–80%；分享率 15–30%；首年付费转化率 1.5–3%；ARPPU ¥20–40。

## 6. 详细功能清单

> 优先级定义：**P0** = 首版必须（MVP，对应差异化三件套 + 合规兜底）；**P1** = 上线后 4–8 周内补齐；**P2** = 观察数据与主体资质后再决定。
> 人天为**单人天**，含前后端与自测，不含整体联调（联调另计 3 人天）。

### M1 输入与引导

**F1.1 首屏三字段极简表单** `P0` `1.5 人天`
- 规则：首屏仅有 3 项——①宝宝姓氏（输入框，支持复姓）②性别倾向（男 / 女 / 中性 / 不限，默认"不限"）③名字字数（单字 / 双字 / 不限，默认"双字"）。底部主按钮「给我灵感」，副按钮「随便看看（不填也行）」。
- 交互细节：姓氏输入框下方实时提示"常见姓氏"快捷标签（张/王/李/刘/陈/杨/赵/黄/周/吴…top 20，按地域可 P1 个性化）。三项均允许为空/默认，任何组合都可点主按钮。
- 验收：
  - Given 用户首次进入，When 页面加载完成，Then 可见字段数 ≤ 3 且无需任何授权弹窗。
  - Given 用户不修改任何默认值，When 点击「给我灵感」，Then 直接进入生成流程，不出现任何必填校验提示。
  - Given 用户输入姓氏"欧阳"，When 提交，Then 复姓被正确识别且不拆分为单姓。

**F1.2 渐进式补充（第二屏，可跳过）** `P0` `1.5 人天`
- 规则：结果页以"抽屉 +  chips"形式提供可选维度增强，全部非必填，随时可改并触发"按新条件换一批"：
  1. **家乡/方言**（多选）：普通话 / 粤语 / 闽南语 / 吴语(苏沪) / 川渝 / 客家 / 湘语 / 赣语 / 东北官话 / 英语环境；可多选，默认按微信 `wx.getSystemInfo` 地区做**建议但不写入**。
  2. **字辈字**（选填，1 字）：如家族有字辈，可指定第 2 字固定。
  3. **避讳字**（选填，≤10 字）：父母/祖辈名中已用字，生成时回避（含同音回避）。
  4. **寄寓期望标签**（≤3 个）：健康坚韧 / 温润内敛 / 聪慧好学 / 豁达开朗 / 坚韧不拔 / 清雅文艺 / 大气开阔 / 小众不撞名。（替代原"父母性格"输入）
  5. **出生季节 / 节气**（选填下拉）：春/夏/秋/冬 或 二十四节气之一 —— **仅用于意象词联想（如"清和""望舒"），不作为任何推算依据**。
- 验收：
  - Given 用户在结果页，When 点击「更多条件」，Then 抽屉弹出，5 个维度全部默认为空且无需填写即可关闭。
  - Given 用户填写避讳字"伟"，When 触发换一批，Then 结果中不含"伟"及其同音字（wěi 全调）。
  - Given 用户未授权或未填写任何增强项，When 使用全部功能，Then 无功能缺失（对照 §4.2 第 6 条）。

**F1.3 明确不采集清单（需求级硬约束）** `P0` `0.2 人天`
- 规则：**禁止采集**——精确出生时间（时分）、出生医院、身份证号、手机号、家庭住址、父母姓名全名、家庭收入/情况描述。
- 父母信息仅采集「姓氏」与「用于连读检测的名字末字（选填单字）」，且**不落库**（见 F9.8）。
- 验收：Given 代码扫描，When 遍历所有 `input` 组件与云函数入参，Then 不存在上述字段；Given 抓包，When 完成一次完整生成，Then 请求体中不含上述字段。

**F1.4 「随便看看」示例模式** `P0` `0.5 人天`
- 规则：不填任何信息进入，使用默认参数 + 预生成缓存池展示一组热门候选，页头明示"以下为示例，填写姓氏后结果更贴合"。
- 验收：Given 未登录未填表用户，When 点击「随便看看」，Then 3 秒内出现 ≥6 个候选，且页面可正常收藏/分享。

**F1.5 授权不阻断** `P0` `0.3 人天`
- 规则：头像昵称、相册、订阅消息授权一律**后置且可拒绝**；拒绝后所有功能照常可用，仅"保存海报到相册"降级为"长按图片保存"。不主动请求地理位置授权。
- 验收：Given 用户拒绝全部授权，When 走完"生成→收藏→生成卡片→分享"全流程，Then 无阻断、无二次强弹。

### M2 生成引擎

**F2.1 本地规则层 · 用字白名单** `P0` `1.5 人天`（含词库整理）
- 规则：白名单 = 《通用规范汉字表》(2013) 8105 字 ∩ 人工标注起名常用字集（目标 3,000–4,000 字）。每条含字段：字、简体笔画、结构类型（独体/左右/上下/包围/框架）、字义褒贬标签（褒/中/规避）、性别倾向（男/女/中性/-）、是否多音、是否繁体异体、现代使用频度档位（常见/适中/小众/罕见）。
- **任何候选字不在白名单即整条丢弃并重新生成**，不做"提示后保留"。
- 验收：Given 白名单表，When 随机抽检 1,000 个生成结果，Then 100% 用字命中白名单；Given 白名单外字（如"龘"），When 引擎产出，Then 被拦截且日志可查。

**F2.2 音律规则层** `P0` `1 人天`
- 规则：基于拼音库（含多音字在姓名中的常见读音）计算：①姓氏与名字的声调组合，避开"三连同调""全仄"等拗口组合 ②声母/韵母重复检测（如 l-l-l、zh-i-zh-i）③连读拗口检测（如韵母结尾 + 零声母开头产生的吞字）。输出为**描述性标签**（如"声调起伏：平–仄–平""与姓氏连读流畅"），**禁止输出分数**。
- 验收：Given 名字"李莉丽"，When 过音律层，Then 被标记为"声母重复，连读拗口"并降权；Given 名字"林清和"，Then 输出"平–平–平，声调起伏平缓"描述且不被降权。

**F2.3 谐音与歧义规则层（差异化核心 ①）** `P0` `1.5 人天`
- 规则：三张表并行命中即降权/丢弃——
  1. 普通话不雅谐音表（自建，含常见网络用语与身体/贬义联想）
  2. **方言谐音表**：按方言区映射发音（粤语 Jyutping、闽南 POJ、吴语、川渝、客家、湘、赣），命中该方言下负面/滑稽联想即对该用户降权并提示
  3. **外语发音歧义表**（跨文化检测）：以英语为主的常见负面联想音节清单（如易被读成常见贬义词、易被误读为难发音、易产生尴尬缩写），命中即提示
- 输出为**结论 + 说明文本**（"在粤语中读作 X，与 Y 同音，可能引发联想"），禁止分值与"不吉/不祥"类表述。
- 验收：Given 用户选择粤语，When 生成结果中含粤语负面谐音候选，Then 该候选被过滤或显式标注提示；Given 用户未选方言，Then 仅执行普通话检测；Given 用户选择"英语环境"，Then 跨文化检测卡片出现。

**F2.4 敏感词与合规过滤（双层）** `P0` `1 人天`
- 规则：输入侧（姓氏/期望词/留言）与输出侧（名字/释义/出处）均调用 `msgSecCheck`（含 `openid` 场景 2 与媒体场景可选），叠加自建：贬义字表、不雅字表、政治人物姓名表、知名商标/名人重名黑名单、高危词表（§4.3）。任一命中 → 输入侧替换为空并提示，输出侧整条丢弃并记录。
- 验收：Given 输入含违规词，When 提交，Then 被拦截且给出中性提示"换个说法试试"；Given 输出命中黑名单，Then 该条不出现在结果页且进入审核日志。

**F2.5 重名度 / 字频层** `P0` `0.8 人天`
- 规则：基于公开姓名用字频率数据（公安部《姓名报告》公布的高频字 + 开源字频），给出**分档描述**：常见 / 适中 / 小众 / 罕见；同时展示单字在近年新生儿名字中的使用位次曲线（图表）。**只做分档与曲线，禁止"重名率 87%"式精确数字与评分**。
- 验收：Given 结果页，When 查看任一候选，Then 可见分档标签 + 曲线图，页面无百分制/星级/分数元素。

**F2.6 AI 生成层 · Prompt 与结构化输出** `P0` `1.5 人天`
- 规则：Prompt 输入 = 白名单约束 + 用户偏好标签 + 若干示例 + 硬性禁止项（禁止出现 §4.3 词表、禁止编造出处、禁止输出评分）。输出严格 JSON Schema：
  `{name, pinyin[], chars:[{char, meaning, structure, strokes}], overall_meaning, source:{author, title, sentence}|null, imagery_tags[], style_tags[], gender_tendency}`
- 模型选型：**禁用高幻觉推理模型做最终输出**（DeepSeek-R1 21.02%、Qwen3-235B 28.92%）；主选 doubao-1.5-pro（4.11%）或同等低幻觉模型，备选 qwen-max。出处字段**必须**由 F2.7 本地校验通过后才允许透出。
- 验收：Given 每次调用，When 返回非 JSON 或 Schema 校验失败，Then 触发重试（≤2 次）后走 F2.8 兜底；Given 返回内容含高危词，Then 被 F2.4 拦截。

**F2.7 出处本地三元组校验（工程兜底 ②）** `P0` `1.2 人天`
- 规则：本地诗词/典籍语料库（5,000–10,000 条，仅收录**公有领域**古籍：诗经、楚辞、先秦诸子、汉魏六朝、唐诗、宋词；**不收录现代人的译文/赏析**）。AI 返回 `source` 后，校验 (作者, 篇名, 原句) 三元组**全部命中**本地语料才允许展示；否则 `source` 置空，前端**不显示出处理由、不显示"无出处"、不编造**。
- 验收：Given AI 返回一句编造的"出自《诗经·XX》"，When 过校验，Then 出处模块隐藏且日志记 `source_reject`；Given 正确三元组，Then 展示并可点击查看原文上下文（上下句）。

**F2.8 预生成 + 流式 + 降级兜底** `P0` `1.5 人天`
- 规则：三段式节奏——
  1. **0–2s**：先渲染 6 个"即时候选"（来自本地规则池 + 参数指纹缓存），配合骨架屏，解决"等待太慢"。
  2. **2–12s**：AI 候选以流式分批追加（每批 4–6 个），制造"在认真想"的感知（目标总时长 **5–15 秒**）。
  3. **兜底**：AI 单次超时 >8s 或连续失败 2 次 → 切备用模型；仍失败 → 纯本地规则池 + 模板化寓意文案，前端显示"本次由本地字库为您挑选"（非错误态）。
- 验收：Given 正常网络，When 触发生成，Then 2 秒内首屏有候选、12 秒内累计 ≥20 个；Given 模拟 AI 全量故障，Then 仍能返回 ≥12 个候选且无报错弹窗；Given 弱网，Then 有明确加载态与"重试"按钮。

**F2.9 结果合法性流水线** `P0` `0.8 人天`
- 规则：所有候选（含本地池）必经同一管道：白名单 → 贬义/敏感 → 普通话谐音 → 方言谐音（按用户选择）→ 外语歧义（按用户选择）→ 音律降权 → 重名度分档 → 避讳/字辈冲突 → 出处校验。任一硬失败即丢弃，软失败（音律/重名度）仅打标。
- 验收：Given 一次生成，When 查看流水线日志，Then 可回溯每个候选的每一步结果与丢弃原因；Given 最终候选数 <12，Then 自动放宽软条件并再生成一轮。

**F2.10 结果缓存与去重** `P0` `0.5 人天`
- 规则：参数指纹 = hash(姓氏 + 性别 + 字数 + 方言集合 + 期望标签 + 风格 + 字辈 + 避讳)。命中缓存直接返回（含跨用户共享池，但需先过 F2.4 个性化过滤）。同一用户同指纹 24h 内不重复调用 AI。
- 验收：Given 同一指纹第二次请求，Then 无 AI 调用记录且结果稳定；Given 跨用户命中共享池，Then 成本看板 AI 调用次数不增加。

**F2.11 成本与限流** `P0` `0.4 人天`
- 规则：单用户每日生成上限 20 次、每分钟 3 次；全局 QPS 上限与日预算熔断（达预算 80% 告警，100% 切纯本地池）。看板展示：日调用数、单次成本、丢弃率、超时率。
- 验收：Given 压测 3 倍峰值，Then 有限流提示且无雪崩；Given 日预算耗尽，Then 自动降级且用户侧无报错。

- 验收：Given 排除"梓涵"，When 换一批，Then 不再出现该组合；Given 未登录收藏后登录，Then 本地收藏自动合并无重复。

**F3.6 重名度 / 字频可视化** `P0` `0.6 人天`

- 验收：Given 图表页，Then 标注数据来源与统计年份，无"重名率 %"表述。

**F3.7 方言谐音检测卡（差异化核心 ①-A）** `P0` `0.6 人天`

- 验收：Given 开启该维度，Then 每张候选卡可见 1–3 条提示；Given 无联想命中，Then 展示"未发现明显跨文化歧义"。

- 规则：仅当 F2.7 校验通过才显示「出处」模块：书名 + 篇名 + 原句 + 释义，并提供"查看上下文（上下句）"。校验不通过 → **整块不渲染**，不留占位、不解释。
- 验收：Given 100 条生成结果，When 统计，Then `source_reject` 结果数 / 总结果数 被记录且目标 ≤15%；Given 抽查 20 条展示的出处，Then 100% 能在本地语料中精确匹配。

**F3.11 政务与系统兼容提示** `P0` `0.5 人天`

**F3.12 换一批 / 调参重生成** `P0` `0.4 人天`

### M4 家庭决策（差异化核心 ②）

**F4.1 我的候选池** `P0` `0.6 人天`
- 规则：跨会话保存收藏的名字，支持排序（收藏时间/重名度/自定义）、备注（≤30 字，过审）、删除。

**F4.2 家人共选 · 投票** `P0` `1.5 人天`

- 验收：
  - Given 家人点击分享卡片，When 进入小程序，Then 无需登录即可投票。

**F4.3 投票结果可视化** `P0` `0.5 人天`
- 规则：展示每个候选的喜欢票数、留言列表、投票人数；按票数排序；提供"多数人喜欢"的中性文案（**不使用"最佳/第一名"等排名词**，避免与名字打分混淆）。

**F4.4 长辈视角说明（原"说服长辈的话术武器"的合规化实现）** `P0` `1 人天`
- 规则：为每个候选生成一段《给长辈的说明》，模板结构固定为 4 段：①这个字是什么意思 ②出自哪本书（仅当出处校验通过）③好不好写、好不好认、能不能上户口（客观维度结论）④我们希望孩子成为什么样的人（用户填写的寄寓标签）。

**F4.5 命名说明书导出** `P0` `1.5 人天`
- 规则：将候选池 + 释义 + 出处 + 方言检测结论 + 长辈视角说明 + 免责声明 + AI 生成标识，导出为**长图（P0）**，PDF 为 P1。支持保存到相册、分享到会话、打印。

**F4.6 最终选定与后续引导** `P1` `0.6 人天`
- 规则：点击"就选它" → 生成正式名字卡片 + 上户口材料清单提示（**信息性提示，非法律建议**，附官方链接）。

## 7. 关键流程

### 7.1 首次起名流程

```
[打开小程序]
   │ 展示首页：3 字段 + 「给我灵感」+「随便看看」
   ▼
[点击「给我灵感」] ──(可选)── 授权弹窗（拒绝不阻断）
   │
   ▼
[0-2s] 本地规则池 + 缓存 → 首屏 6 个候选（骨架屏过渡）
   │
   ▼
[2-12s] 云函数 genName → AI 分批流式追加（每批 4-6 个）
   │        ▲
   │        └── 每条必经：白名单 → 敏感 → 谐音(普通话/方言/外语)
   │                     → 音律 → 重名度 → 避讳 → 出处三元组校验
   │                     （硬失败丢弃，软失败打标）
   ▼
[结果页] 候选卡片流 + 风格分组筛选 + 客观维度标签
   │
   ├──(收藏)──→ 我的候选池 ──→ 发起家人共选 ──→ 生成卡片/说明书 ──→ 分享家庭群
   ├──(排除)──→ 记录原因 ──→ 后续生成不再出现
   └──(换一批/调条件)──→ 回到生成（保留收藏）
```

**关键节点指标**：首屏候选 ≤2s；完整结果 ≤12s；首次生成完成率 60–80%。

### 7.2 家人共选流程

```
发起人：候选池勾选 3-6 个 → 创建共选房间（7 天有效期）
   │        → 生成小程序卡片（脱敏：无生日/无父母名/无家庭情况）
   ▼
分享到家庭群  ──(禁止"转发解锁"权益)
   ▼
家人点击卡片 → 免登录匿名身份（openid 哈希去重）→ 投票（喜欢/再想想）+ 留言(≤50字)
   │                                                    │
   │                                                    ▼
   │                                        msgSecCheck + 自建词表（先审后发）
   ▼
发起人查看：票数排序 + 留言（昵称脱敏）+ 长辈视角说明
   │
   ▼
选定 → 正式名字卡片 + 命名说明书长图（含 AI 标识 + 免责声明）
   │
   ▼
7 天后房间归档，链接失效，留言清除
```

### 7.3 生成质量兜底流程

```
AI 调用
  ├─ 成功 → JSON Schema 校验
  │           ├─ 通过 → 合法性流水线 → 出处三元组校验
  │           │            ├─ 通过 → 展示出处
  │           │            └─ 不通过 → source 置空，出处模块不渲染，记 source_reject
  │           └─ 失败 → 重试 ≤2 次 → 仍失败 ↓
  ├─ 超时 >8s → 切备用模型 → 仍超时 ↓
  └─ 连续失败 2 次 → 切备用模型 → 仍失败 ↓
                                    ↓
                      【降级：纯本地规则池 + 模板寓意】
                      前端文案："本次由本地字库为您挑选"（非错误态）
                                    ↓
                      仍不足 12 个 → 放宽软条件（音律/重名度）再生成一轮
                                    ↓
                      仍不足 → 展示已有结果 + "调整条件试试"（不硬凑、不空屏）
```

## 9. 数据结构与技术架构建议

### 9.1 技术栈
- 前端：**微信小程序原生**（WXML/WXSS/TS）+ 少量 Skyline 特性；组件库用 WeUI 或自研轻量组件（避免体积）。
- 后端：**微信云开发 CloudBase**——云函数（Node.js 18）、云数据库（MongoDB 兼容）、云存储、静态托管（管理后台）、云调用（免鉴权调 msgSecCheck）。
- AI：低幻觉模型（doubao-1.5-pro 优先，qwen-max 备选）经云函数代理，密钥存云函数环境变量，绝不下发客户端。
- 本地词库：以 JSON/索引文件形式随云函数包发布或存云存储 + 冷启动加载到云函数内存（注意包体与内存上限，>10MB 建议走云存储 + 缓存层）。

### 9.5 关键性能与容量假设
- 单用户单次生成返回 20–40 个候选；跨用户缓存池目标覆盖 ≥30% 请求。
- 出处库与白名单建议常驻云函数内存（预计 5–15MB），冷启动 <1.5s；若超限改云存储 + Redis 式缓存（云开发无 Redis，可用数据库 + 内存 LRU）。
- 目标 DAU 1,000 时，日 AI 调用 ≤3,000 次，月成本中位 ¥150–350。
